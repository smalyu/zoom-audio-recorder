# Работа с проектом

Zoom Audio Recorder — локальное приложение для macOS 15+, записывающее звук Zoom и Яндекс Телемоста, микрофон и, по желанию, видео экрана. Интерфейс и документация для пользователей — на русском.

## Устройство

- `Sources/App.swift` — SwiftUI-интерфейс, модель состояния, меню, разрешения и режим `PREVIEW`.
- `Sources/zoom-audio.swift` — захват звука, определение mute и говорящих в Zoom, временные шкалы, журнал и управление записью.
- `Sources/Telemost.swift` — поиск Телемоста в приложении и браузерах, состояние микрофона и объединение встреч.
- `Sources/Sessions.swift` — хранение сессий, экспорт, проверка файлов и восстановление после сбоев.
- `Sources/Screen.swift` — выбор окна или экрана, видеозахват и видеодорожки.
- `Sources/Echo.swift` — подавление эха с помощью Accelerate.
- `Tests/` — исполняемый набор тестов с синтетическим звуком и видео; точка входа в `AudioTests.swift`.
- `Resources/` — Info.plist, entitlements и иконка; `scripts/` — сборка и инструменты разработки.

Проект собирается напрямую через `xcrun swiftc`, без Swift Package Manager и `.xcodeproj`. Используйте существующие скрипты, а не `swift test` или `xcodebuild`.

## Проверки

Нужны macOS 15+ и выбранный полный Xcode (`xcode-select -p`).

```sh
zsh scripts/check.sh    # Все исходники для arm64 и x86_64, обычный режим и PREVIEW, затем тесты
zsh scripts/test.sh     # Только тесты на архитектуре текущего Mac
zsh scripts/preview.sh  # Снимки состояний интерфейса в светлой и тёмной темах
```

- После изменений Swift-кода или скриптов проверки запускайте `zsh scripts/check.sh` и сообщайте результат.
- После изменений интерфейса также запускайте превью и просматривайте затронутые состояния в обеих темах. Снимки находятся в `build.noindex/previews/`.
- Тесты не требуют действующего созвона или разрешений на запись. Реальные разрешения, устройства и поведение Zoom/Телемоста проверяются отдельно при изменениях соответствующей интеграции.
- Список исходников в `scripts/test.sh` задан явно и не включает `App.swift`, поскольку у тестов своя точка входа. При добавлении исходника обновляйте этот список по необходимости.
- Для исправлений добавляйте тесты на наблюдаемое поведение в существующий набор. Изменения только документации не требуют запуска Swift-проверок.
- Результаты сборки, кеши и временные артефакты храните в игнорируемом `build.noindex/`.
- GitHub Actions запускает ту же команду `check.sh` на macOS при push и pull request.

## Правила изменений

- Сохраняйте совместимость с macOS 15 и обеими архитектурами: `arm64` и `x86_64`.
- Следуйте существующему стилю Swift: четыре пробела, небольшие функции, комментарии о причинах нетривиальных решений. Сохраняйте текущую структуру и системные фреймворки, пока задача не требует другого.
- Сохранность записи — основной инвариант: не перезаписывайте существующие файлы и не удаляйте исходные части до успешного сохранения и проверки результата. Сохраняйте восстановление после аварии и возможность повторить неудачное сохранение.
- Сохраняйте временные шкалы звука, обработку задержек и смены устройств. Остановка и сохранение должны завершаться даже при зависших операциях захвата.
- Микрофон в общей записи зависит от mute в Zoom/приложении Телемоста. Неизвестное состояние обрабатывается существующим механизмом отдельной копии микрофона. Для Телемоста в браузере действует описанное в README ограничение: пишется весь микрофон и звук браузера во время звонка.
- Работа приложения остаётся локальной: записи и диагностика не отправляются во внешние сервисы.
- Сохраняйте существующие незакоммиченные изменения пользователя; ограничивайте правки текущей задачей.

## Сборка и выпуск

```sh
zsh scripts/build.sh    # Универсальное .app, ресурсы и подпись
zsh scripts/package.sh  # DMG из готового .app; при Developer ID — нотарификация
```

`build.sh` использует Developer ID из Keychain либо постоянную локальную identity из `prepare_local_signing.py`. `package.sh` устанавливает вспомогательные Python-пакеты в `build.noindex/packaging/` и при наличии Developer ID отправляет приложение и DMG в Apple через профиль `zoom-audio-recorder`.

Используйте `check.sh` для обычной проверки кода. Запускайте сборку с подписью и упаковку, когда задача требует сборки приложения или подготовки выпуска. Версии в `Resources/Info.plist` меняйте в рамках задачи выпуска.
